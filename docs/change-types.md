# Change Types

## Feature
New user-visible or system capability.

Requires: requirement brief, acceptance criteria, tests, rollout/rollback note.

## Bugfix
Correction of broken behavior.

Requires: reproduction, root cause, regression test, before/after evidence.

## Small change
Low-risk edit: copy, config, narrow logic, non-breaking API adjustment.

Requires: short impact note and smoke validation.

## API change
Endpoint, schema, contract, auth, status code, payload, integration behavior.

Requires: compatibility check, contract note, integration test.

## Business logic change
Change to rules, calculations, eligibility, pricing, workflow decisions.

Requires: rule source, examples, edge cases, business tests.

## Refactor
Internal change intended to preserve behavior.

Requires: no behavior-change statement, test evidence.
